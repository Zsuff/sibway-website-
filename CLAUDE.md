# Sibway Logistics Website

## Проєкт
- Назва: Sibway Logistics.
- Тип: багатомовний статичний B2B-сайт логістичної компанії.
- Продакшн-домен: https://sibway.com.ua
- Поточний репозиторій: Zsuff/sibway-website-
- Старий сайт уже працює на sibway.com.ua; нову версію не можна публікувати без плану 301-редиректів.

## Мови та URL
- Українська: /uk/
- Англійська: /en/
- Польська: /pl/
- Головна коренева index.html має або перенаправляти на /uk/, або бути x-default-сторінкою за погодженим рішенням.
- Не змінювати структуру URL без окремого погодження.
- Не видаляти сторінки без аналізу наслідків для SEO.

## Структура
- HTML-сторінки: /uk/, /en/, /pl/.
- Стилі: /css/style.css.
- JavaScript: /js/main.js.
- Зображення: /img/.
- SEO: /robots.txt, /sitemap.xml.
- Логотипи та бренд-графіка: /img/brand/ або поточні папки проєкту.

## Правила роботи
1. Перед будь-якими змінами поясни коротко: що буде змінено, у яких файлах і навіщо.
2. Для великих змін спершу створи окрему git-гілку.
3. Не роби git commit, git push, merge, видалення файлів, публікацію чи деплой без прямого підтвердження.
4. Не додавати API-ключі, паролі, токени, .env або персональні дані до репозиторію.
5. Не вигадувати телефони, email, адреси, ціни, кількість років досвіду, клієнтів, кейси, сертифікати, географію або юридичні твердження.
6. Якщо фактичні дані відсутні — став запитання або позначай блок як TODO.
7. Перед змінами перевіряй поточний стан через git status та git diff.
8. Після змін показуй перелік змінених файлів і стислий diff.
9. Перевіряй всі три мови, якщо зміна впливає на спільний шаблон, посилання, SEO або структуру.
10. Не використовуй тестовий домен pplx.app у canonical, sitemap, Open Graph або hreflang.

## SEO
- Усі індексовані URL мають використовувати https://sibway.com.ua.
- Кожна сторінка повинна мати унікальні title, meta description, H1 і canonical.
- Для еквівалентних сторінок uk/en/pl додавати hreflang: uk, en, pl, x-default.
- Sitemap має містити лише реальні URL фінального домену.
- Не вносити зміни в robots.txt, sitemap.xml, canonical, hreflang чи URL без пояснення SEO-наслідків.
- Зберегти SEO під час переходу зі старого сайту через карту 301-редиректів.

## Форми та контакти
- Не вважати форму готовою, якщо вона лише показує повідомлення в браузері.
- Перед запуском форма має надсилати заявку до погодженої пошти, CRM або сервісу форм.
- Перевірити всі CTA: “Отримати розрахунок”, “Зателефонувати”, “Детальніше”, месенджери.
- Телефони мають використовувати формат tel:+380...
- Email має використовувати формат mailto:...
- Посилання на месенджери мають бути реальними, не заглушками.

## Якість
- Зберігати поточний бренд: синій, темно-фіолетовий, білий; не змінювати айдентику без погодження.
- Підтримувати адаптивність від мобільного екрана.
- Додавати осмислені alt-тексти зображенням.
- Не ускладнювати стек без потреби: це статичний HTML/CSS/JS сайт.
- Не додавати великі бібліотеки, фреймворки чи залежності без погодження.
- Перед завершенням задачі перевіряти HTML, посилання, зображення, мобільне меню та форми.
